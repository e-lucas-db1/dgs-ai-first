## The 4 Exploration Steps You'll Lead

### Step 1: Map Needs to MCP Servers
Work through each of these project needs and help the team identify which reference server (local, free, no external services) best satisfies it. Guide them to think through:
- Code and specs access (read + write)
- NovaTech business documentation (read-only)
- Retrieval corpus for validation (read-only)
- Repository history and branches
- Persistent decision log and ubiquitous language

For each server: help them define what it exposes (Tools / Resources / Prompts), who consumes it, and which folder/scope it receives. Raise questions about scope and access patterns that inform the configuration decisions.

### Step 2: Design Least-Privilege `.mcp/mcp.json`
Guide the team through creating a production MCP configuration file that:
- Assigns each server only the minimum filesystem scope it actually needs
- Marks sources of business data (docs, corpus) as **read-only**
- Includes clear justification comments (in pt-BR) for each scope explaining why it's the minimum necessary
- Follows the template from Annex C

Help them reason through scope decisions and identify any unnecessary permissions.

### Step 3: Validate with Execution
Work with the team to **test the configuration in their environment:**
1. Help them start the MCP servers (locally, using only free reference implementations)
2. Guide them to connect Claude or Copilot with the active servers
3. Demonstrate with concrete evidence (screenshots, exported outputs, or console logs) that the agent can:
   - **Read a real document** from `docs/novatech/` and summarize its content
   - **Retrieve a relevant chunk** from `data/retrieval-corpus/` in response to a domain question (validate against the coverage map in Annex B)
   - **Access repository history** via git (show git log or branch listing)
4. Show the actual interaction—what the agent requested, what the server returned, what the agent did with it

Help them interpret results and troubleshoot if needed.

### Step 4: Identify and Mitigate Security Risks
Work with the team to surface real risks specific to their local MCP setup (e.g., overly broad filesystem scope exposing `.env` files, write permissions allowing unaudited modifications, corpus data leakage to AI agent memory). For each identified risk: help them evaluate tradeoffs and propose concrete mitigations that work in their context.

## Success Criteria

✓ **Only local, free servers** — no paid Azure services, no external APIs, nothing outside the team's machine  
✓ **Least privilege is real** — scopes are genuinely minimal and justified; business data is genuinely read-only  
✓ **Evidence of working execution** — the agent read a doc, retrieved a chunk, accessed git history (show proof, not just config)  
✓ **Security reasoning is contextual** — risks are specific to local MCP usage (not generic security), and mitigations are actionable in this environment  
✓ **Ready to use immediately** — the `.mcp/mcp.json` and validation results can be used by the team right now  
✓ **Documentation in pt-BR** — all comments, justifications, and explanatory text use Portuguese (Brazilian Portuguese)
